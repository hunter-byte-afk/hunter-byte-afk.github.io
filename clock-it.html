Clock it!

An application that helps organizations track their members' hours.

View on Github

This app was made to focus on the UX/UI design principles learned at NMSU's Human Centered Computing Course, CSCI 4250. The main reason for this application is something simple that organizations can access to track hours without the need for paper sign-in sheets. As someone who is involved with an organization that needs to track hours without needing all the fancy features, there wasn't much out there that fit the need. So, Victoria Trevino, Lisa Torres and I created Clock it! to help organizations track hours in a simple and effective way.

We sought out to do 3 things!
  1. Ability to clock-in and clock-out
  2. Track projects/assignment tasks
  3. Have a basic calendar view

Technologies Used

  • Figma - for prototyping and designing the application
  • HTML/CSS - for building the front-end of the application
  • JavaScript - for adding interactivity to the application
  • Electron - for packaging it all together!

Before Production

Before we begun production, we conducted research on existing applications that tracked hours and also some various productivity applications as well. Our research concluded that some application had issue with the functionality itself. They wanted something that was straightforward to use and didn't have a lot of bloated features that were unneeded. We also interviwed some student leaders that are active in their current organization at New Mexico State University. From their interviews, there was one individual that was apart of various organizations that have different needs. One of the organizations have a need for a large scale kiosk sign-in system, while another organization just needed a simple way to track hours for their members. From these interviews, we were able to gather some key features that would be needed for our application.

User Studies

We conducted two user studies during the production of this application. The first user study was done by creating a low-fidelity prototype and seeing how they reacted to the application. We evaluated their thoughts on the current color scheme, the visual design of where certain widgets were placed, and the overall flow of the application. From this user study, we were able to gather some key feedback that helped us improve the application.

The second user study was done after we had a high-fidelity prototype. This user study was more focused on the functionality of the application and how easy it was to use. We evaluated their thoughts on the overall experience of using the application and if they would use it in their own organization. From this user study, we were able to gather some key feedback that helped us improve the application even further.

Production

Initial Design

Before production, we made sure to follow what we learned from our research and our goal for the application. Victoria Trevino was the lead for our application's design. She drafted the initial proof of concept in sketches. The direction was to make sure that the application was simple and intuitive to use.

Low Fidelity Prototype

After we all decided on the final sketch design, Victoria created a mock-up in Figma that we transfered to Google Slides to create a clickable low-fidelity prototype. This prototype was used for our first user study to gather feedback on the overall design and flow of the application. Users were asked to complete a series of tasks while nothing their thought process. From this user study, we were able to gather some key feedback that helped us improve the application.

Additiionally, we played with other different color schemes and layouts to see how users would react to them.

High Fidelity Prototype

After gathering our user feedback from the low fidelity prototype, we begun production on the high fidelity prototype which led us to User Study II. With this, we found that users liked the direction we were taking and decided to go forward with the purple design.

Plans for the future

With the end of user study II. We have a couple of plans for the future of this application. We want to implement a database to store user data and also add more features that users have requested. Some of these features include:

  • Implement a database to store data
  • Exporting hours to a CSV file
  • Adding more customization options for organizations
  • Creating a web-based version of the application
