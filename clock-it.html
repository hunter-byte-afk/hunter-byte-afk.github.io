Clock it!

An application that helps organizations track their members' hours.

View on Github

The secondary purpose of this project was to focus on the UX/UI design principles learned in NMSU's Human-Centered Computing Course, CSCI 4250. The primary reason for this application is a simple solution that enables organizations to track hours without the need for paper sign-in sheets. As someone involved with an organization that needs to track hours without requiring all the fancy features, there wasn't much available that met the need. So, Victoria Trevino, Lisa Torres, and I created Clock it! to help organizations track hours simply and effectively.

We sought out to do 3 things!
  1. Ability to clock-in and clock-out
  2. Track projects/assignment tasks
  3. Have a basic calendar view

Before Production

Before we began production, we researched existing applications that tracked hours, as well as various productivity applications. Our research concluded that some applications had issues with their functionality. They wanted something straightforward to use, without unnecessary, bloated features. We also interviewed some student leaders who are active in their current organization at New Mexico State University. From their interviews, there was one individual who was part of various organizations on campus with different needs. One of the organizations needs a large-scale kiosk sign-in system.

In contrast, another organization needed a way to track the hours worked by its members. From these interviews, we gathered some key features that would be necessary for our application. The primary focus was to ensure it was straightforward to use.

User Studies

We conducted two user studies during the production of this application. The first user study was conducted by creating a low-fidelity prototype and observing how participants reacted to the application. We evaluated their thoughts on the current color scheme, the visual design of where certain widgets were placed, and the overall flow of the application. From this user study, we gathered key feedback that helped us improve the application.

The second user study was done after we had a high-fidelity prototype. This user study focused primarily on the application's functionality and ease of use. We evaluated their thoughts on the overall experience of using the application and whether they would use it in their own organization. From this user study, we gathered key feedback that helped us further improve the application.

Production

Initial Design

Before production, we ensured that we followed the lessons learned from our research and our application's goals. Victoria Trevino was the lead designer for our application. She drafted the initial proof of concept in sketches. The goal was to ensure that the application was intuitive and straightforward to use.

Low Fidelity Prototype

After we all agreed on the final sketch design, Victoria created a mock-up in Figma, which we then transferred to Google Slides to create a clickable, low-fidelity prototype. This prototype was used for our first user study to gather feedback on the overall design and flow of the application. Users were asked to complete a series of tasks while noting their thought process. From this user study, we gathered key feedback that helped us improve the application.

Additionally, we experimented with various color schemes and layouts to observe how users would respond to them.

High Fidelity Prototype

After gathering user feedback from the low-fidelity prototype, we began production on the high-fidelity prototype, which led us to User Study II. With this, we found that users liked the direction we were taking and decided to go forward with the purple design. With this version of the project, we concluded development for the time being, with the ability to scale up through testing multiple users, implementing security, and collaborating on specific tasks.

What I Learned

I learned a few things from this project. One of the more useful ones I learned about is diving deeper into the tools we plan to use and how to rescope. Additionally, I have deepened my understanding of using JavaScript, HTML, and CSS together.

Plans for the future

With the conclusion of User Study II. We have several plans for the future of this application. We aim to implement a database to store user data and add additional features that users have requested. Some of these features include:

  • Implement a database to store data
  • Exporting hours to a CSV file
  • Adding more customization options for organizations
  • Creating a web-based version of the application
  • Add user types, i.e., admin and officers.
